# Contribution Guidelines:
## Preface:
This document serves as the guidelines for contribution.
Last Updated: 9/21/2026
When contributing via pull request or commit, you must follow these guidelines using the tolerance gauge below.

- Preferred: Encouraged.
- Accepted: Allowed in general.
- Tolerant: Not advised, not problematic.
- Questionable: Advised against.
- Rejected: Banned in general.

## PRACTICES
### AI
- WRITING/FIXING: Rejected. Generative AI models are too vulnerable to hallucination when used in massive sections, which can result in excessive errors and misunderstood code.
- GENERAL TESTING: Tolerant. Using AI models to evaluate code to find odd vulnerabilities, weird bugs, and other issues is tolerated. When found, make an issue citing the method, and what happened.


### MANUAL:
- COMMENTING: Preferred. Document your code so other developer, inside and out, can understand the logic of your reasoning.
- SELF-DOCUMENTING ISSUES: Accepted. Anything not ideal within the code you have written can be documented as an issue or a comment in the code by you.


## BEHAVIOR
- ARROGANCE: Questionable. Some arrogance is okay, especially when discussing with other developers, where you have a point to your idea. However, too much is not okay.
- HARASSMENT/BULLYING: Rejected. Defined as hurting someone with words repeatedly. Fastest way to get banned from contributing.
